# Changelog

`CHANGELOG.md` is the extension's release notes, and roam.pub shows it at `/updates` (What's new) next to the website's; nothing there is generated from commits. Every change users would notice adds a bullet in the same commit, under `## Unreleased` and a `### Area` (reuse one: Commands, Status link and change log, Publishing, Setup and settings…). Start each bullet with its kind: `Breaking:` (something that worked stops working as before, or needs people to act; say what to do), `New:` (something you couldn't do before), `Improved:` (works better) or `Fixed:` (was broken). roam.pub shows `Breaking:` bullets with a red label (from website 0.17.1). A release renames `## Unreleased` to `## x.y.z (YYYY-MM-DD)` when it's sent to Roam Depot (its `source_commit`). roam.pub shows only the changelog at the commit Roam Depot serves, so nothing appears there until Roam Depot picks the release up, and it's timestamped then. Write for the people who use the extension, one change per bullet, wrapped lines indented. Leave out tests, refactors, build tooling and fixes too small to notice. The Changelog check fails a PR into `main` that changes `src/` without touching `CHANGELOG.md`; label it `no-changelog` when there's genuinely nothing to log.

# Versions and roam.pub

roam.pub names the exact oldest extension version it works with. The version in `package.json` is sent with every request (`x-roam-publish-version`), roam.pub answers with its minimum (`x-roam-publish-min-version`), and an older extension asks people to update (`checkMinVersion` in `src/api.ts`). It also sends `x-roam-publish-can-seal` (`1` when Roam has X25519, so pages can be encrypted in Roam), because a release that refuses plain Password pages has to wait for everyone to be able to encrypt, not just to update; every new request header has to be allowed in roam.pub's CORS (`src/lib/cors.ts`) on its `main` before a release sends it. The extension's and roam.pub's majors don't have to match. A release that needs something new from roam.pub ships only after roam.pub's `main` has it, because Roam Depot updates people's extensions on its own schedule. roam.pub only removes something an extension relies on once everyone active in the last 30 days is on a version that doesn't need it (its production deploy refuses otherwise), announced first at roam.pub/updates/upcoming (roam-publish-web's CLAUDE.md). Bump the extension's major only when it removes something people rely on, with a `Breaking:` bullet; other changes bump the minor or patch.
