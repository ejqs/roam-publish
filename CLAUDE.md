# Changelog

`CHANGELOG.md` is the extension's release notes, and roam.pub shows it at `/updates` (What's new) next to the website's; nothing there is generated from commits. Every change users would notice adds a bullet in the same commit, under `## Unreleased` and a `### Area` (reuse one: Commands, Status link and change log, Publishing, Setup and settings…). Start each bullet with its kind: `New:` (something you couldn't do before), `Improved:` (works better) or `Fixed:` (was broken). A release renames `## Unreleased` to `## x.y.z (YYYY-MM-DD)` when it's sent to Roam Depot (its `source_commit`). roam.pub shows only the changelog at the commit Roam Depot serves, so nothing appears there until Roam Depot picks the release up, and it's timestamped then. Write for the people who use the extension, one change per bullet, wrapped lines indented. Leave out tests, refactors, build tooling and fixes too small to notice. The Changelog check fails a PR into `main` that changes `src/` without touching `CHANGELOG.md`; label it `no-changelog` when there's genuinely nothing to log.

# Versions and roam.pub

The extension and roam.pub are compatible while they share a major version. The version in `package.json` is sent with every request (`x-roam-publish-version`), and roam.pub answers with the oldest version it works with, `{its major}.0.0`; an older extension asks people to update (`checkMinVersion` in `src/api.ts`). A release that needs something new from roam.pub ships only after roam.pub's `main` has it, because Roam Depot updates people's extensions on its own schedule. For a breaking change to the API, roam.pub first adds the new shape beside the old one, then the extension moves to it as its next major, then roam.pub drops the old shape as its own next major once everyone has updated (roam-publish-web's CLAUDE.md). Keep the extension's major for that: other changes bump the minor or patch.
